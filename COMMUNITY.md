# Типы аккаунтов, достижения и никнеймы — прототип

## Страницы

- `authors.html` — мультиселект типов аккаунтов. Выбранные типы объединяются по условию «ИЛИ». Пустой выбор показывает всех авторов. Выбор сохраняется в параметре `types` ссылки.
- `/aestube/delis` — профиль PRO: бейдж, никнейм, миниатюры достижений и раскрывающаяся коллекция.
- `/aestube/delis?collection=1` — полученные награды внутри профиля. Ссылка «Ещё 5 ›» раскрывает блок и меняется на «Свернуть ‹». Отдельного пункта меню, вкладки, заголовка коллекции, фильтров и кнопки обмена всей коллекцией нет. Подробности отдельной награды остаются в её всплывающем окне.
- `/aestube/delis?collection=1&achievement=top10` — прямое открытие подробностей конкретного достижения. Старые ссылки `collection.html` перенаправляются на раскрытый блок профиля.
- `profile-settings.html` — установка, изменение и очистка никнейма в кабинете PRO.

## Демонстрационная модель

Типы аккаунтов, даты регистрации, просмотры и результаты рейтингов заданы в `assets/community.js`. Это примеры интерфейса, а не утверждение о подтверждении врачебного статуса или реальных достижениях владельцев аккаунтов.

У аккаунта ровно один тип: автор, врач или обучающий центр. PRO — отдельная платная возможность, не второй тип аккаунта. Бейдж обычного автора скрыт; «Врач» серый без галочки. Высота бейджей типа и PRO — 24 px. В лентах «Актуальное» бейджи типов не выводятся.

У Делис отображается только PRO, у Dr Davin Lim только «Врач», у energyclinic.ufa — «Обучающий центр», одинаково на главной, в списке авторов и в профилях. Существующий адрес Dr Davin Lim по никнейму сохраняется; новые никнеймы по-прежнему настраиваются только в кабинете PRO.

Нажатие на аватар с обводкой или закреплённую обложку открывает полноэкранное модальное окно плеера поверх текущей страницы. Закрытие возвращает к этой же странице без перехода в раздел «Актуальное». Состав очереди публикаций зависит от места запуска и остаётся прежним.

Девять оригинальных мини-иллюстраций в `assets/achievements/` выполнены в SVG. Получение наград рассчитывается из демонстрационных событий: месячных рейтингов, годовщин регистрации и суммарных просмотров. За месяц выдаётся одна рейтинговая награда соответствующего уровня: лучший автор, Топ-10 или Топ-25. Повторные получения сохраняются в истории. У Делис награда Топ-10 получена дважды, последнее получение — 11 июня 2026.

Во всплывающем окне награды оставлены иллюстрация, описание, автор и даты получения. Заголовок «История получения», кнопки «Моя» и «Поделиться» удалены. Неполученные награды в коллекции не показываются.

## Никнейм PRO

Допустимы 3–30 символов: латинские буквы, цифры, дефис и подчёркивание, первый символ — буква. Регистр приводится к нижнему. Проверяется совпадение с другими демонстрационными авторами и зарезервированными именами. Очистка поля возвращает числовой ID в ссылку. Старые ссылки по ID продолжают открывать автора.

Ссылки на авторов с никнеймом теперь имеют вид `/aestube/delis`, `/aestube/dr-davin-lim` и `/aestube/people-skin`. Для этих трёх адресов созданы статические каталоги с `index.html`, поэтому прямое открытие и перезагрузка работают на GitHub Pages без 404. После стандартного перенаправления на каталог конечный слэш убирается в адресной строке через History API. Корень ресурсов фиксируется тегом `base`. Локальный HTTP-сервер показывает эти же страницы как `/delis` и т. п.

Старые ссылки `author.html?nickname=...` и ссылки с ID продолжают работать. Если у автора задан никнейм, адрес автоматически заменяется коротким, с сохранением параметров раскрытой коллекции и выбранной награды. У авторов без никнейма остаётся `author.html?author=30`.

Изменения никнейма хранятся только в localStorage данного браузера (`aestube-author-profiles-v1`). Новый пользовательский никнейм не регистрируется глобально и не будет найден в другом браузере. На GitHub Pages неизвестные серверу локальные никнеймы обрабатываются через `404.html` — это демонстрационный fallback с HTTP-статусом 404, а не полноценный серверный маршрут. Обычный локальный `python3 -m http.server` такой fallback не поддерживает; для произвольных новых никнеймов локально нужен сервер с подстановкой `404.html`. Ссылки с исходными демонстрационными никнеймами работают для всех посетителей со статусом 200. В рабочем сайте необходимы полноценный серверный роутинг, проверка PRO, глобальная уникальность никнеймов, реальное начисление наград и постоянное хранение истории.
